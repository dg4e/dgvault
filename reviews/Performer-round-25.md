# Performer — Round 25 (verifiable cores of the device-gated features)

The correction from R24: *writing* the device features doesn't need a device —
*verifying on real hardware* does. So this round builds the pure, testable cores
of three "platform" features and pushes the device/network/hardware part behind a
thin interface (the SecureStore/KeyVault pattern). Each core is verified against
an INDEPENDENT implementation, not just self-consistency.

## 1. YubiKey challenge-response — `lib/core/security/challenge_response.dart`
`ChallengeResponse` factor interface + `SoftwareChallengeResponse` computing
HMAC-SHA1(secret, challenge) — exactly what a YubiKey does on-token — feeding
`CompositeCredential.challengeResponse`. **Verified against RFC 2202 HMAC-SHA1
vectors** (cases 1–3). The USB/NFC token is a device-gated transport implementing
the same interface.

## 2. Cloud sync engine — `lib/data/sync/`
`RemoteStorage` abstraction (+ in-memory fake) and `SyncEngine`: convergent
pull → 3-way LWW merge (reusing the existing `DatabaseMerger`) → push. **Verified
with the REAL `KdbxCodec`** (Argon2 + AES + HMAC stream) over a fake remote:
two-device convergence, no-op re-sync, newer-remote-wins and newer-local-wins
conflict resolution (`sync_engine_test.dart`). The concrete OneDrive/Drive/
Dropbox/iCloud/SFTP/WebDAV/Nextcloud/SharePoint adapters (OAuth + HTTP) are the
account/network-gated part — they just implement `RemoteStorage`.

## 3. WebAuthn / passkeys (RP verify side) — `lib/core/webauthn/`
The relying-party verification a passkey login performs, minus the transport:
- `cbor.dart` — minimal RFC 8949 decoder (the WebAuthn subset).
- `cose_key.dart` — COSE_Key → ES256 (P-256) public key + DER-ECDSA verify.
- `authenticator_data.dart` — flags/signCount/attested-credential-data parse.
- `webauthn.dart` — `verifyRegistration` ('none' + 'packed' self-attestation) and
  `verifyAssertion` (signature over authData ‖ SHA-256(clientDataJSON), rpId + UP/
  UV checks, returns signCount for clone detection).
**Verified against an independent vector** generated by Python `cryptography` +
`cbor2` (`test/fixtures/webauthn/`, regenerator committed): registration extract,
valid-assertion accept, tampered-clientData/-signature reject, wrong-rpId reject.
The private-key side (Secure Enclave / platform authenticator key creation +
signing) is device-gated; EdDSA + x5c attestation-chain validation are follow-ups.
